# 智能任务管理系统（task-manager）

Node.js（Express）+ React（Vite）+ Supabase（PostgreSQL）的全栈任务管理小项目。

## 功能

- 顶部输入框写任务标题，下拉选择优先级（高 / 中 / 低），点「添加」入库
- 任务列表按创建时间倒序显示（最新在最上面）
- 每条任务显示：标题、优先级标签、完成状态
- 每条任务可「标记完成 / 标记未完成」、可「删除」
- 已完成任务自动加删除线、颜色变淡
- 顶部按优先级筛选：全部 / 高 / 中 / 低
- 数据存在 Supabase 云端 PostgreSQL，刷新不丢

## 一、本地运行

```bash
npm install

# 在 Supabase 建好 tasks 表（见下）后，复制环境变量
cp .env.example .env
# 编辑 .env 填入 SUPABASE_URL 和 SUPABASE_ANON_KEY

# 启动后端（端口 3000）
npm run server

# 另开终端，启动前端（端口 5173，/api 已代理到 3000）
npm run dev:client
```

浏览器打开 http://localhost:5173 。

## 二、Supabase 建表 SQL

在 Supabase 的 SQL Editor 依次执行：

```sql
-- 建表
create table if not exists tasks (
  id bigint generated by default as identity primary key,
  title text not null,
  priority text not null default '中' check (priority in ('高', '中', '低')),
  completed boolean not null default false,
  created_at timestamptz not null default now()
);

-- 打开 RLS 策略（教学演示用，允许任意读写；正式项目请改成登录用户只能操作自己的数据）
alter table tasks enable row level security;
create policy "Allow anon read" on tasks for select using (true);
create policy "Allow anon insert" on tasks for insert with check (true);
create policy "Allow anon update" on tasks for update using (true) with check (true);
create policy "Allow anon delete" on tasks for delete using (true);
```

然后在 Project Settings → API Keys 复制：
- `SUPABASE_URL`：`https://xxxx.supabase.co`
- `SUPABASE_ANON_KEY`：`sb_publishable_xxx`

## 三、部署到 Vercel

1. 把本仓库推到 GitHub（Public）。
2. Vercel → Add New → Project，导入该仓库。
3. Environment Variables 里添加：
   - `SUPABASE_URL`
   - `SUPABASE_ANON_KEY`
4. Deploy。完成后访问 `https://xxx.vercel.app`。

> 注意：`.env` 已在 `.gitignore` 中，不要把 `sb_publishable_` 之外的密钥（`sb_secret_...`）提交到 GitHub。
